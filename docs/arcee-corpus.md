### Arcee: what it does
`star-arcee-what` · page /work/arcee

A desktop agent for Ubuntu. Say or type what you want, and it plans the request, does it with your apps, and tells you what happened. “How much free disk space do I have?” “Move the installers in Downloads to the trash.” “Turn the volume down to 30.” Arcee carries requests like these out on your own desktop, printing every step as it goes. Talk or type: A wake word trained from three samples of your voice, transcripts from Groq Whisper, and spoken replies through Kitten TTS. Or just type: arcee-cli run "…". Uses your computer like you do: Files and the shell, your real signed-in Chrome, desktop apps through the accessibility tree, plus mail, calendar, reminders, music and WhatsApp. Asks before it touches anything: Reading is automatic. Anything that changes files stops at “Allow? [y/N]”. Commands like rm -rf and sudo are refused outright. Any model, any role: By default gpt-oss-20b, qwen3.8-27b and gpt-oss-120b on Groq, rotated within each one's free budget. Pass --core local and everything stays on your machine through Ollama.

### Arcee: how it works
`star-arcee-how` · page /work/arcee

Not a prompt with tools bolted on: a harness. A planner for long requests, a step loop that calls one tool at a time, and guards around every action. Every request flows through the same loop, and every step is logged with secrets redacted. Hear: sherpa-onnx keyword spotting and Silero VAD wake it; Groq Whisper writes the transcript. Plan: Long requests get a plan first; short ones go straight to the loop. Act: A step loop calls one tool at a time and reads the result back. Hard steps climb a ladder to a stronger model. See: With no accessibility tree to read, a vision model picks cells on an 8×6 grid of the screen, then a zoomed 6×6, to find what to click. Guard: Every action passes a policy tier and the shell classifier; web and file content is marked untrusted. Remember: SQLite with full-text search. Recall weighs 60% match, 25% recency (14-day half-life) and 15% importance. Report: A spoken or written answer, with the full run in arcee-cli history.

### Arcee: key decisions
`star-arcee-decisions` · page /work/arcee

Groq by default, local on request: The default core runs on Groq, rotating models by each one's budget (8,000 tokens a minute, 200,000 a day). --core local keeps every request on the laptop. Context beat a bigger model: A small local model went from 3/8 to 7/8 on the same cases with better context alone, so the harness feeds context before it reaches for size. Plan only long requests: Planning costs a model call, so it only happens when the request needs one. Chrome through an extension: A small extension lets Arcee read and act in your real, signed-in browser instead of a fresh headless one.

### Arcee: safety rules
`star-arcee-guards` · page /work/arcee

Three tiers: auto, confirm and never. The never-list holds even when a command hides behind ;, && or $(…). Confirm before changes: Anything that writes, moves or deletes waits for a yes. Deleting goes to the trash, not rm. Untrusted text can't steer it: If a web page or file contains instruction-like phrases, the next action needs your confirmation, whatever its tier. Risky clicks ask first: Buttons named delete, send or pay always ask before Arcee clicks them. Refused outright: sudo, su, pkexec, dd, fdisk, mkfs, shred, shutdown, reboot, passwd, useradd, iptables, ufw, writes to /etc and /usr.

### PatentIQ: what it does
`star-patentiq-what` · page /work/patentiq

Universities want students to file patents, but most drafts need work first. PatentIQ reads a draft and scores it the way a reviewer would. A mentor sets up a group, students upload their drafts, and each one comes back scored with what to fix before filing. No account for students: Mentors create groups and share a public link; students submit through it without signing up. A score out of 100: Eleven weighted dimensions, from inventive step and novelty to claims and commercial potential, plus strengths, weaknesses and a refined inventive concept. Citations and copying, checked: Every patent a draft cites is looked up in live patent search, and the text goes through a plagiarism scan. Built for mentors: A dashboard with analytics, every submission, a live view of the pipeline, retries, Excel export and PDF reports.

### PatentIQ: how it works
`star-patentiq-how` · page /work/patentiq

Context first: the patents a draft cites are checked against live databases before the model grades a word of it. A deterministic stage runs before the generative one, so the model reasons from verified patents, not from memory. Extract: Patent IDs are pulled from the draft with regex and text patterns. Verify: Each ID is looked up in live patent search (Serper), giving a ground-truth list of valid and invalid citations. Evaluate: The PDF and that list go to the model (Gemma by default), which returns structured JSON, sanitised before use. Check: Copyleaks scans for plagiarism, and the evaluator looks for its own canary phrase. Persist: Reports land in Cloudflare D1, files in R2; pipeline logs, a dead-letter table and retry counts record every stage.

### PatentIQ: key decisions
`star-patentiq-decisions` · page /work/patentiq

Edge router, heavy service: A Cloudflare Worker handles routing, auth and storage; an Express service on Render does the slow work: PDFs and model calls. Deterministic before generative: The citation check runs first, so the model is grounded in which patents actually exist before it judges anything. Integrity as a formula: +3 for each valid patent cited, up to +15, and −5 for each invalid one, applied by the model alongside a verdict from Excellent to Fraudulent. A canary in the report: Each PDF report hides an invisible line. Paste it into an AI to rewrite the draft and the phrase comes back: the resubmission scores 0 and is rejected in code.

### About this website
`fact-1` · page /

iteshxt.me is built with Next.js, React, TypeScript and Tailwind CSS, hosted on Vercel, and designed by Itesh. Its look is die-cut stickers on a cutting mat. Peeling the top-right corner like a sticker switches between light and dark. Every page has its own idea: Work is a shipping manifest, each case study is an opened case file, About is a laptop lid covered in stickers, DiaLabs is a lab notebook whose pages turn as you scroll, and Contact is a postcard you can actually send.
